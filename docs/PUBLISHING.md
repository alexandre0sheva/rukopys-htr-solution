# Hugging Face and GitHub Publishing

This project is safe to publish as open source when generated data, model artifacts, and credentials
stay out of Git. Use your own namespaces in every publishing command.

Copy [.env.example](../.env.example) to `.env` and fill in your own values. The `rukopys` CLI reads
`.env` automatically; sourcing is only needed for shell commands that reference variables directly,
such as `git remote add origin "$GITHUB_REMOTE"`:

```bash
cp .env.example .env
set -a
source .env
set +a
```

## Hugging Face Dataset Upload

Authenticate:

```bash
hf auth login
hf auth whoami
```

Create and upload the curated dataset:

```bash
rukopys upload-dataset \
  --dataset-dir data/curated/rukopys_mvp
```

The curated folder includes a Hub-compatible `README.md` dataset card generated by the curator.
Use `--private` only when you intentionally want a private Hub repo.

For larger uploads, prefer the resumable CLI uploader:

```bash
hf upload-large-folder \
  "$HF_DATASET_ID" \
  data/curated/rukopys_mvp \
  --type dataset
```

## Hugging Face Model Upload

Upload after local training:

```bash
rukopys upload-model \
  --model-dir runs/qwen3_vl_8b_page_qlora
```

Or push from the training command:

```bash
rukopys train-vlm-qlora \
  --train-jsonl data/curated/rukopys_mvp/page_sft.jsonl \
  --base-model Qwen/Qwen3-VL-8B-Instruct \
  --output-dir runs/qwen3_vl_8b_page_qlora \
  --push-to-hub
```

The training output is a PEFT/LoRA adapter folder plus processor files. Inference can load that
adapter folder directly. The upload commands use `HF_DATASET_ID`, `HF_MODEL_ID`, `HF_NAMESPACE`,
and `HF_PRIVATE` from `.env`; explicit CLI flags still override them.

## GitHub Upload

```bash
git status
git add .
git commit -m "Prepare RUKOPYS HTR pipeline"
git remote add origin "$GITHUB_REMOTE"
git push -u origin main
```

Keep these out of Git:

- `data/`
- `runs/`
- `outputs/`
- `.venv/`
- `.pytest_cache/`
- `.ruff_cache/`
- `.DS_Store`
- `.env`
- Hugging Face tokens
